# 投递复盘与登记草稿

先确认数据能支持什么，再给下一步。只读台账，输出诊断与草稿，不把未知算成失败，不凭版本名称猜“当前版”。

## 输入

优先读取本次对话材料。经用户授权可按需读取当前项目可选的 `.qiuzhi/LEDGER.csv`、`.qiuzhi/PROFILE.md`、`.qiuzhi/EVIDENCE.md`、`.qiuzhi/PROGRESS.md`、`.qiuzhi/SOURCES.md`。没有文件也能处理粘贴记录；不要求先建库。仅在缺口会改变判断时最小追问。

先读 [台账与闸门](references/ledger-schema.md)。文件是规范 CSV 时，用 Skill 自带的 [版本脚本](scripts/version_gate.py)，脚本路径相对本 `SKILL.md`，不是用户项目根目录。使用说明与示例见 [台账与闸门](references/ledger-schema.md)。粘贴记录按同一规则逐行划分，明确这是人工核对，不能声称跑过脚本。格式不同或脚本报错时说明错误，可分析已经明确的事实，不自动改写原台账。

## 判断流程

1. 划分干净、污染、未知样本，报告各类 ID、数量与状态计数。用户已确认的当前版本允许清单与每行实际版本核实缺一不可。零干净样本时，当前简历效果只能判样本不足。
2. 再按岗位方向、渠道、招呼语版本和观察期分组。当前状态只是快照，不能据此编造历史转移或每层转化率。未知状态、未知版本、尚未观察充分的记录不记失败。
3. 用四层检查定位可能问题，证据不足标待确认，不能必然归因。

| 层 | 需要的证据 | 可采取的改进 |
|---|---|---|
| 岗位匹配 | JD 职责与个人经历对应关系 | 缩小职责范围，补齐硬条件与证据映射 |
| 开场沟通 | 实际招呼语、是否触达／已读、沟通环境 | 让岗位意向与相关经历更容易看懂，减少无关内容 |
| 简历证据 | 干净版本且确认已发出／被查看的记录、原稿与具体反馈 | 把职责与个人行动对应，核查结果与数字口径 |
| 后续推进 | 已有实质沟通、对方要求、约定节点与真实进展 | 补对方需要的资料，在约定时间跟进或明确暂停 |

不同渠道可能先展示在线简历，再显示招呼语。不能宣称前两层天然不受版本影响；须核实具体曝光顺序。`resume_sent` 只证明已发，不证明已读；`closed` 只证明结束，不等于被拒。日期不足以单独证明等待时间充分。

4. 给固定三行复盘：

```text
断点：第几层／暂不能定位；列依据、样本范围与不确定项。
修法：只修最有依据的问题；若证据不足，先做可验证的核对。
下 3 条动作：分别说明下一条、第二条、第三条记录或投递准备改变什么，以及验收标准。
```

动作交由用户实施，不自动投递。不能为凑三条强迫用户新增投递；单条请求只给本条的必要动作。

5. 登记请求则给规范字段的草稿行和缺失字段清单；日期、公司、状态、版本不猜。使用 `csv` 等可靠方法正确转义；空值表示未知，不能写“待核实”冒充枚举。更新请求列出指定 ID 的原值与拟修改值。

## 交付和边界

交付闸门结论、三行复盘或登记草稿、会影响结论的缺口。草稿明确未写入；实际写入请求交 `qiuzhi-agent`，已有授权随交接保留，不反复确认。纯方法交 `qiuzhi-course`，个人困境陪练交 `qiuzhi-coach`，跨域组合交 `qiuzhi-dispatch`。入口未安装时提供可复制的交接提示词，不依赖兄弟目录。

支持产品、运营等非销售岗位。不改招呼语／简历正文，不重写整份简历，不做销售岗内容，不自动外发、投递或公开个人材料。方法说明是本包的通用建议；引用用户提供材料须标来源、日期与事实范围，不虚构课程出处。
