# 求职执行

用户点名要什么，就完成相应成品。先恢复对话中的目标、材料和授权，按 [执行与验收](references/workflows.md) 选择场景。只有模糊处境或跨入口任务时，按名称交给 `qiuzhi-dispatch`；入口未安装就提供可直接复制的交接提示词，不假装已经调用。

## 输入与证据

优先使用本次对话材料。经用户授权，可按需读取当前项目的 `.qiuzhi/PROFILE.md`（目标与约束）、`.qiuzhi/EVIDENCE.md`（经历证据）、`.qiuzhi/LEDGER.csv`（投递记录）、`.qiuzhi/PROGRESS.md`（进度）、`.qiuzhi/SOURCES.md`（来源导航）。这些文件全是可选项，不要求用户先建库；粘贴 JD、经历或记录同样可用。路径相对当前项目，不相对 Skill 安装位置。

只问会改变成品的实质缺口，已有信息不重复问。每条事实分别标为已确认、待核实、仅内部或不宜公开；用户确认、可读取的证据、推断分别记录。一个项目部分已确认，不代表所有数字都已确认。内部分析可保留缺口；对外成品只用用户授权用于该成品的已确认事实。用户提供材料不等于同意公开整份材料。

## 执行顺序

1. 明确交付物、用途及输入；无需让用户批准常规写作计划。
2. 拆出岗位需求与个人证据的对应关系；没有证据就留空或写待核实，不能靠措辞补全经历。
3. 生成所需成品。缺少非必要事实时省去该句，不因局部缺口冻结整件工作。
4. 逐句核验人名、岗位、数字、时间、个人贡献及承诺；按参考文件验收。涉及指定 PDF 等格式时检查实际渲染结果，不能以源稿冒充最终格式。无法渲染则明确交付限制。
5. 交付正文或用户指定位置的文件，附简短证据说明与未解决项。仅在授权范围内落盘；不覆盖既有定稿，默认另存新版本。编辑已有台账前重读最新版，写后检查行数、ID 和字段。

## 边界

- 支持产品、运营等非销售岗位，不限定个人旧方向。按职责判断销售属性；仅凭岗位名称不能定性。明确销售岗位不生成求职成品，说明依据；职责不清时保留判断。
- 不代投递、不代发消息、不默认发布或上传个人材料；成品交回用户。
- 不重写整份简历。局部经历改写不改其他部分；需要整份重写时说明边界。
- 纯方法问题交 `qiuzhi-course`；判断与体检交 `qiuzhi-coach`；台账诊断与登记草稿交 `qiuzhi-delivery`。明确要求实际写入本地台账，由本入口执行，不要求重复授权。
- 不虚构工具结果、公司事实、业绩或来源；团队成果与个人贡献分开，无证据的排名和能力强度不写入成品。

## 完成条件

交付物与请求一致、事实逐项可追溯、缺口明确、格式可使用。落盘时报告路径及实际检查结果；未执行发送、投递等动作，不将草稿描述为已发送。
