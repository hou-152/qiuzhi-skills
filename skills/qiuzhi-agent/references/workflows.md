# 执行与验收

下表是本包的通用工作方法，不代表任何课程讲者的原话。按需要读取，不要求所有场景一起执行。

| 场景 | 最小输入 | 执行与交付 | 验收 |
|---|---|---|---|
| JD 拆解 | JD 正文；个人匹配判断另需经历 | 分开列工作任务、交付结果、硬条件、偏好条件；再列已有证据、缺口、值得确认的问题 | 每项要求能定位到 JD；雇主未写的期待标推断；没有经历仍可完成岗位分析，不编匹配分数 |
| 招呼语 | 岗位及一条相关的已确认经历 | 给一版简短正文，含岗位意向、相关证据及自然的沟通请求；已知且有关的到岗条件才写 | 不堆标签，不补数字，不承诺未知到岗时长；无证据时给明确标注的结构草稿，不冒充可直接发送成品 |
| 局部经历 | 原段落、真实行动与结果、目标用途 | 围绕目标／本人行动／结果重排；明确个人负责范围；另列删改说明 | 原文没有的新事实不能写入；团队结果不得全部归个人；不扩大到整份简历 |
| 面试稿 | 目标岗位、用户经历、需准备的问题 | 按问题给可口述回答：背景、选择理由、本人行动、结果及复盘；补可能追问与证据缺口 | 回答可由本人解释；未做过的动作不改成做过；不给编造的绩效或动机 |
| 公司背调 | 公司主体或可定位的招聘页、用户关心点 | 先核主体，再查业务、岗位职责与招聘条件；列已证实信息、冲突、待面试确认项 | 动态事实实时查证，带来源链接与核查日期；优先官方与原始来源；评论只作线索，查不到明确写未知；无联网能力则仅分析给定材料 |
| 求职日志 | 本日实际动作与进展 | 分已完成、得到的反馈、未完成原因、下一步 | 不把计划写成成果，不代写不存在的反馈；没有记录则给空白结构 |
| 本地台账写入 | 明确写入请求、目标路径、实际发生事件 | 重读文件，保留现有记录，新增唯一 ID 或更新指定 ID；缺字段留空并说明；修改后核对 | 不由草稿推断已投递；不猜版本核实状态；不顺手改历史或其他记录 |

## 可选 CSV 台账

新建 CSV 仅在用户已要求建立台账时执行，使用 UTF-8 或 UTF-8-SIG，固定表头：

```csv
id,date,company,role,resume_version,version_verified,greeting_version,status,stage,next_action,notes
```

`id` 非空且唯一。`status` 仅为 `contacted`、`read_no_reply`、`replied`、`resume_sent`、`interview`、`offer`、`closed` 或空；空表示未知。`version_verified` 只允许 `true`、`false` 或空，只有核实本条实际使用版本后才写 `true`。日期未知留空，已知建议 `YYYY-MM-DD`；其他缺失字段留空，在交付中说明。`stage` 是已有证据支持的阶段描述，不是强制评分。

CSV 用标准库 `csv` 或等价可靠工具读写，正确处理逗号、引号和换行。现有文件格式不同则遵守用户项目规范；不未经授权迁移格式。诊断版本时交 `qiuzhi-delivery`，按其脚本与规范处理。

## 对外件人工核验

逐项检查：事实来源、个人与团队归属、数字单位与统计范围、日期与承诺、岗位相关性、公开范围、是否存在未替换的占位符。发现问题先修正文再交付。这里只提供人工验收，不宣称执行了包内不存在的 lint。用户只要模板时可保留清楚标出的占位符，并标注为模板。
