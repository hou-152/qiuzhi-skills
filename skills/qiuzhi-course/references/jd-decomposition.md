# JD 拆解

用途：把岗位描述变成实际任务和证据要求，避免只匹配名词。

判断标准：能够区分任职硬条件、日常职责、优先项和未说明事项。职位名称不能代替职责全文。

步骤：
1. 保存岗位原文与日期，分开摘出资格条件、职责、工具和协作对象。
2. 对每项职责标出做什么、作用于谁或什么、期待怎样的交付。原文没有结果标准时记为待问，不自行补成公司目标。
3. 用真实经历逐项对应，区分直接做过、相邻经验可迁移、需要实际练习、目前不满足。
4. 对已有证据追查本人动作、判断依据与验证方法；只会术语不等于完成过任务。
5. 把影响投递的未知项写成问题，例如职责优先级、数据权限、试用期交付；不要默认所有列项权重相同。

拆解表字段：原要求｜任务与对象｜交付标准或未知｜硬条件与优先级｜证据类型｜缺口｜验证动作。

验收：每项结论对应原文或明确的推断；迁移能力与直接经验没有混淆。缺经历可以讲解表格，不能据此断言某个人能胜任。实际拆解用户 JD、写定向成品交执行入口。
